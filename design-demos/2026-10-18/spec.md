# BlueMark 本轮设计范围

本轮只做全局走查、方法检索与可比较的方向原型。现有 `src/`、`server/`、路由、业务数据和测试不修改。用户选择后再落地。

## 用户已确认的判断

保留现有架构布局、真实可操作的案例和图片。去掉工作区中装饰性的英文眉题、口号与功能解释，不去掉必要的状态、合规、密钥和错误信息。

1. 用户原话：「不要出现‘WORKSPACE / OVERVIEW 从一个好 Brief，开始下一次品牌增长。’这种在功能按钮上面下面进行解释的内容」。
2. 用户原话：「整体架构布局其实还不错，而且有真实的案例和图片」。其中内置案例实际为完整虚构示例，不能改成已验证的客户成果。
3. 用户原话：「landing页的设计思路是对的，但是需要再优化一下……看不出来是产品介绍页，反而容易误导为已经进入了功能页」。
4. 用户原话：「所有的元素太平面了，且关键功能按钮没有设计没有差异感，点击后没有动态感，层次感等」。

## 共同内容与边界

三个方向使用同一组业务事实，只比较设计。数字均来自默认本地示例，不补造客户、业绩、使用量或满意度。

1. 工作台：2 个项目、1 个案例、11 条待审核内容；两个山野气泡茶示例项目；案例预算 30 万元、周期 30 天。
2. 导航仍为总览、项目、新建方案、内容工厂、案例库、使用记录、模型配置、设置。不增加新功能层级。
3. 产品介绍页明确使用「产品」「工作流程」「案例」等访客导航，主操作为「进入工作台」；产品 UI 放在明确的产品预览舞台，不做实际工作区的连续延伸。
4. 原型覆盖产品介绍页与工作台总览两个视图。工作台新建、案例打开、标签切换、菜单/弹窗与保存反馈可交互，仅在原型内存中运行，不读写正式业务存储、不请求模型。
5. 统一验证尺寸：1440×1000 网页窗口，375×812 窄窗口。正文至少 14px，标签至少 12px；按钮 44px 高，表格行内工具可用视觉 20px 图标和 44px 点击区域。
6. 只使用既有品牌标志、真实 UI、草本茶照片。照片不是山野气泡茶包装图，案例中保留「示例」标识。

## 形式推导

工作台首先为反复处理营销项目的人服务；产品介绍页首先为面试官和首次访客服务。两者视觉任务不同。

| 五问 | 工作台 | 产品介绍页 |
| --- | --- | --- |
| 叙事角色 | 操作与判断 | 认识产品及决定进入 |
| 观看距离 | 笔记本网页，持续阅读 | 笔记本网页，快速扫读 |
| 温度 | 清晰、果断、有可信反馈 | 有品牌感，但不是科技宣传 |
| 容量 | 最近项目、待审任务、案例入口；不靠空话填充 | 品牌、产品类别、一个真实产物、主次入口 |
| 独有结构 | Brief → 方案 → 审核 → 导出；项目与案例相连 | 将 Brief 与可交付方案的真实截面并置 |
